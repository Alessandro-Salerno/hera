# Contributing to Hera

## Why contributions matter
Simply put, I'm a busy person. I am a university student, I already work on
[a large number of projects](https://github.com/Alessandro-Salerno), and
unfortunately I lack limitless knowledge. I believe this project can be of real
use to some people (me included), but I currently lack the resources to make it
"great".

If you have some spare time and knowledge to share, I'd greatly appreciate your
help.

## Who can contribute
Contributions are welcome regardless of the author's background, as long as they
are relevant to the project and comply with all necessary standards (e.g., legal,
project, community, etc.). 

## How to contribute
You may contribute by any regular open-source means, including:
- Bug reports
- Feature suggestions
- Code contributions
- Documentation improvements

Code contributions are especially welcome given the early stage of the project
and [the already lengthy list of scheduled tasks](https://github.com/Alessandro-Salerno/hera/issues).

## Branch policy
Starting from the moment of the publication of this repository, the `main`
branch will act as the reference "stable" branch. Contributors are encouraged
to create a new branch for each contribution they intend to make and name it
according to the standard: `<type>/<short description>`. Branch types may include:
- `feat`: new feature
- `chore`: general maintenance
- `fix`: bug fixes
- `docs`: documentation improvements
- `refactor`: code changes without effects on behavior
- `test`: test improvements

## Commit naming
Starting from the moment of the publication of this repository, contributors
will be encouraged to adopt a reasonably consistent and clean naming convention
for commit messages. An example would be the use of conventions similar to those
described in the previous section. 

## Code quality and standards
Contributions are expected to follow existing conventions and standards used
across the code base. These are described in more detail in [`docs/conventions.md`](./docs/conventions.md).

## Contribution workflow
1. Fork the repository
2. Create a new branch 
3. Make your changes
4. Format the code using the provided `.clang-format` configuration
5. Commit to your branch
6. Open a pull request

## AI policy
The use of Artificial Intelligence and other generative tools is allowed,
provided the contributor checks and tests the validity and correctness of the
generated material, ensures it complies with this document, and discloses the
use of said technologies.
